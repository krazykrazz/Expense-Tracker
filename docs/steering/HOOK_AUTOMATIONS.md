# Hook Automations and Task Checklists

This document captures the intent of local Kiro hooks in a repository-tracked form so the same expectations are visible to all contributors.

## Origin

These checklists were derived from local Kiro hook automations and are now tracked in-repo as the canonical source.

## Requirement Review Checklist

Run this checklist whenever creating or updating a feature spec:

1. Confirm all relevant feature actions are represented in activity log behavior (new events, updated events, deletions when applicable).
2. Identify and include safe cleanup/refactor opportunities discovered while implementing the feature.
3. Update relevant docs, including architecture, roadmap, README, and any published user/developer docs affected by the change.
4. Verify test guardrails are followed according to `docs/steering/TESTING_STRATEGY.md` and related enforcement scripts.

## Test Task Update Checklist

When a task requires full-suite, full-backend, or full-frontend validation, use `scripts/run-test-summary.ps1` variants instead of ad-hoc commands.

Standard commands:

```powershell
# Standard (sequential but optimized)
.\scripts\run-test-summary.ps1

# Fast development mode
.\scripts\run-test-summary.ps1 -FastPBT

# Parallel execution (fastest)
.\scripts\run-test-summary.ps1 -Parallel

# Maximum speed
.\scripts\run-test-summary.ps1 -FastPBT -Parallel
```

Operational notes:

- Budget 10-15 minutes for full test runs and use suitable command timeouts.
- Analyze failures using `test-failure-summary.txt` generated by the script.
- Avoid splitting full verification into disconnected backend/frontend commands for checkpoint gates.
